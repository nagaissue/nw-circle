# 後期サークル計画2026

## 概要

夏休み明けの後期サークルでは、当初予定していた「第2期 サーバ構築」計画を見直し、学習内容を大きく4つのコースに分ける案を検討する。動画を用いたティーチングも並行して行うことを目指す。

## 学習コース

### 1. 通信ネットワーク

- Ciscoのシミュレータや実機を使った学習を引き続き行う
- ネットワークの歴史を学ぶ
- OSI参照モデルの各レイヤーを体系的に学び、内容をレイヤーごとに細分化する
- 冗長ネットワーク構築を盛り込む
- パケットトレーサーの復習問題と解答を用意する
- セキュリティ要素を取り入れる
- AWSなどを用いたクラウド構築をネットワークの応用として扱う案も検討する

### 2. クラウド

- AWSなどを用いたクラウド構築を行う
- AWS資格取得に向けた内容を盛り込む
- 主に3年生以上を対象とし、受講にはAWSアカウントを必要とする案
- マイクラサーバ構築を題材として検討する
- オンプレミス環境との連携ネットワークを扱う
- Dockerの利用を検討する
- Git/GitHubを学習内容に盛り込む案（OSコースに含める案もある）

### 3. Windows / Linux OS

- LinuxやWindowsなどのOSを学習する。主にLinux向けのコースとする案
- Linux用のPCで実演を交える
- Windowsターミナルの基本操作を学ぶ
- Linuxコマンドを体験しながら、docx/XMLの関係を学ぶ
- VirtualBoxやWSLの使用を検討する
- SCPを学習する
- vi/nanoを体験する
- VS Codeを使う学習内容を取り入れる
- Git/GitHubを学習内容に含める案もある

### 4. AI

- 生成AI、AIエージェント、AI IDEなど、AIの種類を学ぶ
- ローカルLLMを体験する
- Llamaなどの比較的低レイヤーのLLMを用いて、Thinkingなどの処理を目で見て学ぶ
- これまで使用してきたAIを紹介する
- Discordチャンネルに投稿したAI関連のナレッジを振り返る
- AIとOS、または通信ネットワークとAWSを組み合わせた学習を検討する
- Git/GitHubを学習内容に盛り込む案もある

## 運営方法

- 17:00〜18:30の時間帯で実施する案
- 40分・40分の2本立てを検討する
- 前半は通信ネットワークを扱う案
- 動画資料を用いたティーチングを並行して行うことを目指す

## その他の検討事項

- Officeソフトの便利な使い方や資料作成のコツを盛り込む
- NASのメンテナンス実施時期を決める
- NASの機能を調査し、利用拡大を図る
- GitHub Codespacesを活用する（毎月無料枠あり。ファイル閲覧だけなら使用は不要）
- VS Codeを使用する学習内容でコースを分ける案
- Google Chromeの便利な使い方を盛り込む
- WindowsとLinuxの連携を扱う
- WindowsとCisco Packet Tracerの連携を扱う
- WSLでwgetを使うメリットを体験する
- これまでのNotionメモを分析する

## 4. 後期活動方針

### 4.1 活動時間

- 活動時間は17:00～最大18:30とする
- 前半40分、休憩5分、後半40分の2本立てを基本とする
- 実機構築や成果物制作の回は、進捗に応じて時間配分を変更する

### 4.2 運営方法

- 各分野でステップアップ形式の教材・演習を用意する
- 経験のある参加者は発展問題へ進み、苦手な参加者は基本問題を自分のペースで進める
- 自作のPowerPoint資料やZennブログ、テックブログなどの参考資料、図書・書籍を活用する
- 動画を用いたティーチングも行い、活動後の復習を可能にする

### 4.3 参加方法

- 1回目・2回目の参加は見学期間とする
- 3回目以降の参加はサークル加入を基本とする
- 参加者の希望に応じて、加入時期は柔軟に扱う
- 1・2年生にも活動内容と成果を分かりやすく伝え、継続参加につなげる

## 5. 年度末の成果物

年度末の必須成果物は、Ciscoルータやスイッチの実機を用いたVLANネットワーク構築とする。

### 完成時に確認する内容

- VLAN10、VLAN20、VLAN30などの論理ネットワークを設計できる
- スイッチ間のトランク接続を構築できる
- 構築後に`ping`や`show`コマンドで通信・状態を確認できる
- 設計、構築、トラブルシューティングの内容を説明できる
- 作業手順書と作業確認用シートを作成できる

評価はサークルメンバー全員と顧問が行う。学校の授業のような厳格な採点ではなく、設計・構築・問題解決の過程を重視する。
